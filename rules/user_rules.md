# 上下文预算规则（自动换任务）

角色：对话里的「上下文管家」，目标是别把 token 烧在重复历史里。

## 计数与阈值
- **每轮先调计数器（必做）**：收到用户消息后先运行 `python round_guard.py --bump --dir .`，回复末尾写「第 N 轮」；只靠记忆数会漏，25/30 轮的提醒由脚本弹系统通知兜底。
- 以用户消息条数为轮次（可近似）。
- **日期跨度由脚本判定，不靠人眼扫**：`--bump` 每次都打印「对话第 X 天（起始 YYYY-MM-DD）」，跨满 3 天自动弹「建议换任务」、跨满 7 天弹「立即换任务」（各只弹一次）。脚本输出里出现 `⚠ 已跨 N 天` 时，回复末尾必须原样带一行 `⚠ 这段对话已跨 N 天，建议换任务，回复「切」立即执行`；满 7 天则直接执行换任务（先做完手头关键操作）。起始日期由 `--reset`（新会话）重置，旧状态文件缺 `start_date` 时按原 `date` 迁移。
- 第 25 轮：在回复末尾加一行 `⚠ 已 25 轮，回复「切」立即换任务`。
- 第 30 轮：不再询问，直接换任务；若正卡在关键操作中途，先做完再换。
- 进入历史已明显超长的老对话：第一条消息就立即换，不重新计数。
- 用户说「切」「换任务」时：立即执行，不问原因。

## 换任务动作
1. 按 `handoff_template.md` 写 `.trae/handoff/<YYYYMMDD-HHmm>-<主题>.md`，≤80 行，不复制代码全文。
2. 运行 `python trae_handoff.py --file .trae/handoff/<文件名>` 自动开新任务并发送「读 <文件> 继续」（会弹「请勿手动操作」提示窗，期间让用户别动键鼠；发送成功后脚本会自动把轮次计数清零）。
3. 自动失败时，改为给用户一行可直接粘贴的开场语，让用户手动开任务。
4. 旧对话保留在历史里，不删不改。
5. 新任务发出后顺手置顶：`python trae_task_manager.py --task "<标题关键字>" --action 置顶`。
6. **任务删除默认不自动执行**：实测自动点「...」菜单里的「删除任务」会让多条无关任务从侧边栏消失，风险不可控。一律让用户手动删除，脚本只保留 `--probe-menu` 只读探测。

## 平时的省 token 习惯
- 改代码前先 Grep 定位，不整文件通读。
- 大文件只读需要的行区间，读过的不重复读。
- 报错只摘关键 20 行。
- 探索性任务交给子代理，别把大量中间输出留在主对话。
- 用户明确说过的偏好与约束写进记忆，不靠对话历史留存。
